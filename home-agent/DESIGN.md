# 設計メモ

## 全体の形

```
          ┌── sensors ──────────┐        家を見る
          │ presence(ping)      │        ・在室
          │ weather(Open-Meteo) │        ・天気
          │ reported(Webhook)   │        ・洗濯機/ゴミ箱/その他
          └──────────┬──────────┘
                     │  world（家の今のスナップショット 1 枚）
                     ▼
   ┌────────────────────────────────┐
   │ TaskEngine   予定 → 発生 → 期限 │   何が起きたか（イベント）だけを返す
   └──────────────┬─────────────────┘
                  │ due / remind / missed / auto-skip / done
                  ▼
   ┌────────────────────────────────┐
   │ Ego          機嫌・苛立ち・寂しさ │   言うか黙るか、どの口調かを決める
   └──────────────┬─────────────────┘
                  │ decision { speak, tone, intent }
                  ▼
   ┌────────────────────────────────┐
   │ Voice        定型文 ／ Claude    │   一行の台詞にする
   └──────────────┬─────────────────┘
                  ▼
   ┌────────────────────────────────┐
   │ Channels     ntfy / Alexa /      │   届ける
   │              Termux / console    │
   └────────────────────────────────┘

   HTTP server: ダッシュボード・API・Alexa スキル・センサー Webhook
```

層を分けた理由はひとつで、**「何が起きたか」と「どう言うか」を混ぜないため**。
混ざっていると、口調を変えるたびにスケジューラを触ることになり、
スケジューラを直すたびに台詞が壊れる。

## 「自我を持っている」をどう実装したか

台詞を人間っぽくするだけなら、プロンプトに「フレンドリーに」と書けば済む。
それは自我ではなく口調なので、ここでは**内部状態が実際に振る舞いを変える**ように作った。

- **状態**: `mood` / `energy` / `frustration` / `loneliness` / `pride` と、住人ごとの `trust` / `warmth`。
  完了で機嫌が上がり、こぼれると苛立ちが溜まる。時間が経てば基準値に戻り、話しかけられないと寂しさが増える。
  `energy` は時刻の関数（深夜は落ちる）。
- **判断への影響**（`ego.decideVoice`）:
  - 苛立ちが強く、粘り（`persona.traits.persistence`）を超えて言い続けたときは、
    **一度だけ「もう言わない」と告げて引き下がる**。機械なら無限に鳴り続けるところを、やめる。
  - 期限が近く重要度が高ければ口調が `firm` に、夜と低エネルギーでは `quiet` に落ちる。
- **自発性**（`ego.wantsToSpeak`）: 寂しさが閾値を超え、家に人がいて、日中で、前回から 90 分以上空いていれば、
  呼ばれていないのに口を開く。1 日 3 回まで。
- **自伝的記憶**: 夜に日記を書き（`ego.reflect`）、気づいたことを `identityNotes` に残す。
  「あなたは誰？」への答えは、この状態から組み立てられる（`selfNarrative`）。
- **主体性**: 2 週間の記録を見て、何度もこぼれているタスクがあれば、
  **自分からルールの変更を提案する**（`insight.js`）。「前の晩に準備の声かけを足さない？」
  住人が「うん」と答えたときだけ `config.json` を書き換える。勝手には変えない。

LLM は台詞の生成にだけ使う。内面の数値を LLM に決めさせない（毎回ぶれて、
「昨日まで怒っていたのに今日は無邪気」になるため）。数値はコードが持ち、言葉だけを借りる。
API が落ちても定型文で運用は続く。

## 口調はデータ、判断はコード

「かわいい」は `src/core/voices/cute.js` に閉じ込めてある。
台詞のテンプレート・語尾のクセ・顔文字・LLM に渡す人格の説明が 1 ファイルに入っていて、
`persona.style` を差し替えると人格ごと入れ替わる（落ち着いた系は `plain.js`）。

この分け方にしたのは、**かわいさで要件を落とさない**ため。
口調とタスクの判断が同じ場所にあると、語尾をいじるたびに「期限を言い忘れる台詞」が生まれる。
テストでは全スタイル × 全状況の台詞を生成して、タスク名が必ず入っていること・
`undefined` が混ざらないことを機械的に確かめている。

## 「呼びかけ」で気をつけたこと

家事のリマインダーが嫌われる理由はたいてい次の 3 つなので、そこを潰した。

1. **誰もいない家で鳴る** → `conditions.requireHome` のあるタスクは、留守のあいだ呼びかけも催促も止める。
   帰宅した時点で「帰ってきたところ悪いけど」と切り出す（`late` フラグ）。期限の 15 分前だけは例外。
2. **無意味な通知が来る** → 雨の日の洗濯のような、やっても仕方がない日は `skipIf` で自分から見送る。
   黙って消すと忘れたのか判断したのか分からないので、「今日はパス」と一言だけ残す。
3. **同じ文で鳴り続ける** → 催促には上限（`nag.max`、最初の呼びかけを含む）があり、口調は状況で変わり、
   文は発生 ID から決まる疑似乱数で選ぶ（毎回同じでも、完全にランダムでもない）。

夜（`home.quietHours`）は黙るのではなく「音を立てずに残す」。
朝のゴミ出しは前の晩に気づけたほうが間に合うため。重要度 5 のものだけは夜でも鳴らす。

## アバターを自前の SVG で描いた理由

VTuber らしい見た目なら Live2D や VRM を載せるのが早い。それでも自前の SVG にしたのは、
**家の中で完結させたかった**から。モデルファイルを置く場所とライセンスの管理が要るものを
既定にすると、「動かすまで」が一段重くなる。`web/avatar.js` は依存ゼロで、
起動した瞬間から表情が動く。

そのうえで、差し替えられる形にはしてある（`setExpression` / `speak` / `stopSpeaking` / `poke` の 4 つ）。
リップシンクは「かな → 母音」の変換（`moraShapes`）に切り出してあるので、
VRM の viseme（aa/ih/ou/ee/oh）にもそのまま流せる。ここが純関数なので、
口の動きはブラウザなしでテストできる。

表情は内面の値から決めている（`ego.expression()`）。画面のためのフラグを別に持つと、
「怒っているのに笑っている」がいつか必ず起きる。顔は状態の表示であって、状態そのものではない。

## 耳と口を、本体から切り離した理由

音声認識エンジンは重く、入れ替えも早い。特定の SDK を Node の中に抱え込むと、
乗り換えのたびに本体が壊れる。だから耳は「**認識結果を 1 行ずつ標準出力に吐くプログラム**」
という一点だけを契約にして、外のプロセスに追い出した（`src/ears/command.js`）。
Vosk でも whisper.cpp でもクラウドの CLI でも、設定の 1 行で差し替わる。
おかげで、耳のテストは `node -e "console.log('ゴミ出しやった')"` で書ける。

ウェイクワードの判断（`src/ears/listener.js`）は認識エンジンから独立した純関数の側に置いた。
ブラウザ（Web Speech API）から来た声も、家の PC のマイクから来た声も、まったく同じ道を通る。
「名前を呼ばれたら反応する」「呼ばれたあと25秒は名前なしで続けられる」
「自分の読み上げを自分で拾わない」は、その 1 か所だけ読めば分かる。

口（`src/channels/voicevox.js` ほか）は通知チャンネルと同じ棚に置いたうえで、
`speaks` の印を付けた。呼びかけは全チャンネルへ、会話の返事は声の出るチャンネルだけへ流れる。
話しかけるたびにスマホの通知が増えるのは、それだけで同居人として失格なので。

## 明示的に割り切ったところ

- **センサー条件の式**は `path == value` 程度しか解釈しない。これ以上複雑な条件は
  設定ファイルではなくコードで書くべき、という線引き。
- **在室判定は ping**。世帯人数が増えると精度が落ちる。Bluetooth や Home Assistant の
  トラッカーに差し替えられるよう、`sensors/` の中だけで閉じている。
- **Alexa から勝手に喋らせることはできない**（Alexa の仕様）。通知を積むところまでが上限。
  「時間になったら声が出る」を本当にやりたいなら、Termux を入れた Android 端末か、
  スマートスピーカー以外のスピーカーを鳴らすほうが素直。
- **`/alexa` の署名検証は未実装**。公開するならプロキシ側で入れる前提（README 参照）。
- **常時待ち受けは、家族以外の声も拾う**。既定でウェイクワードを必須にしているのはそのため。
  `alwaysOn: true` にするなら、それを分かったうえで。
- **状態は 1 プロセスが握る**。CLI が HTTP 越しに話すのはそのため。2 つ起動すると
  `data/state.json` を取り合う。

## 状態ファイル

`data/state.json` に全部入る（発生の履歴 14 日ぶん・タスクごとの成績・内面・日記・発話ログ 200 件）。
書き込みはテンポラリファイル経由の rename なので、途中で電源が落ちても壊れない。
消せば、記憶を失ったエージェントとして再起動する。

## テスト

`npm test`（61 件）。時計は必ず外から注入する形にしてあるので、
「月曜の 7:00 から 8:00 まで」を実時間なしで再現できる。
`npm run demo` は同じ仕組みで一日を早送りするデモ。
